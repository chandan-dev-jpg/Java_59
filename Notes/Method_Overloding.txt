=========================================
       METHOD OVERLOADING IN JAVA
=========================================

Definition:
Method Overloading is the process of defining multiple methods with the same name in the same class but with different parameter lists.

OR

Method Overloading allows a class to have more than one method with the same name by changing the number, type, or order of parameters.

-----------------------------------------

Rules of Method Overloading

✓ Method name must be the same.
✓ Parameter list must be different.
✓ Change in:
   • Number of parameters
   • Type of parameters
   • Order of parameters
✓ Return type alone cannot overload a method.
✓ Access modifier may be different.
✓ static and non-static methods can be overloaded.

-----------------------------------------

Example 1 (Different Number of Parameters)

class Demo {

    static void add(int a) {
        System.out.println(a);
    }

    static void add(int a, int b) {
        System.out.println(a + b);
    }

    public static void main(String[] args) {
        add(10);
        add(10, 20);
    }
}

Output:
10
30

-----------------------------------------

Example 2 (Different Data Types)

class Demo {

    static void show(int a) {
        System.out.println("int");
    }

    static void show(double a) {
        System.out.println("double");
    }

    public static void main(String[] args) {
        show(10);
        show(10.5);
    }
}

Output:
int
double

-----------------------------------------

Example 3 (Different Order of Parameters)

class Demo {

    static void display(int a, double b) {
        System.out.println("int, double");
    }

    static void display(double a, int b) {
        System.out.println("double, int");
    }

    public static void main(String[] args) {
        display(10, 20.5);
        display(20.5, 10);
    }
}

Output:
int, double
double, int

-----------------------------------------

Cannot Overload

✗ Only changing the return type.

Example:

int add(int a) {
    return a;
}

double add(int a) {
    return a;
}

Compile-Time Error

-----------------------------------------

Advantages

• Improves code readability.
• Increases code reusability.
• Same method name can perform different tasks.
• Reduces the need for multiple method names.

-----------------------------------------

Method Overloading Resolution

Java chooses the most specific method based on:
• Exact Match
• Widening
• Autoboxing
• Var-args

Priority:
Exact Match > Widening > Autoboxing > Var-args

-----------------------------------------

Important Points

• Achieves Compile-Time Polymorphism.
• Also called Static Polymorphism.
• Happens in the same class.
• Parameter list must be different.
• Return type alone cannot overload a method.

-----------------------------------------

Interview Definition

Method Overloading is the process of defining multiple methods with the same name in the same class but with different parameter lists. It is an example of compile-time polymorphism.

Method Overloading Resolution 
------------------------------------
Method Overloading Resolution is the process by which the Java compiler decides
which overloaded method to invoke at compile time based on the arguments and
the method selection rules.

Priority Order:

1. Exact Match
2. Most Specific Type Rule
3. Widening Primitive
4. Autoboxing
5. Widening Reference
6. Var-Args (Lowest Priority)

Most Specific Type Rule:
If more than one overloaded method is applicable, Java chooses the method
whose parameter type is more specific (closer to the argument type).

double>float --float
float>long ---long
long>int    --int
int >char   
int>short   
short >byte  

Note:there is no relation Between char and short,byte.
Examples:

show(int) + show(long)
show(10);          → show(int)

show(int) + show(double)
show(10);          → show(int)

show(long) + show(double)
show(10);          → show(long)

show(float) + show(double)
show(10);          → show(float)

show(Object) + show(String)
show("Java");      → show(String)

show(10.5);        → show(double)      // Exact Match
show('A');         → show(int)         // char → int (Widening)
show((byte)10);    → show(int)         // byte → int (Widening)
show(10L);         → show(long)        // Exact Match
show(10L);         → show(double)      // If show(long) is absent
show(new Integer(5)); → show(Integer)  // Exact Match
show(5);           → show(Integer)     // Autoboxing (if show(int) is absent)
show(1,2,3);       → show(int...)      // Var-Args (if no better match exists)

Final Rule:
Exact Match > Most Specific Type > Widening Primitive >
Autoboxing > Widening Reference > Var-Args
